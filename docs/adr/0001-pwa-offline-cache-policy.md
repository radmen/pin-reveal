# PWA Offline Cache Policy

Pin Reveal should open with the last successfully loaded app build while offline, then update cached assets in the background when the network is available again. This keeps mobile PIN access available during poor connectivity while still allowing normal app updates after a later online load. The PWA should be installable on Android Chrome and iOS Safari, including the Apple-specific install metadata needed for iOS Add to Home Screen. The PWA assumes the app is hosted from the domain root, so the manifest and service worker can use root-scoped defaults. The service worker should be generated with Vite PWA tooling so hashed build assets are precached reliably. The PWA cache should contain app assets only; labels and generated PINs should remain non-persistent. When a newer build is ready, the app should show a non-blocking top banner with a refresh action instead of auto-reloading or waiting silently for the next launch. Runtime presentation assets, including the Space Grotesk and Space Mono fonts, should be served by the app instead of depending on third-party network requests.
